# College Admissions Library

A shared college-counseling research app with 526 seeded Common Data Set reports. See [school coverage and source limitations](SCHOOL_DATA_COVERAGE.md) for the latest expansion. Original coverage includes: Cornell (1999–2025), USC Columbia (2000–2025), Clemson (2008–2025), Washington and Lee (2005–2025), NYU (2018–2025), Villanova (2023–2025), Michigan Ann Arbor (1998–2025), TCNJ (2014–2025), and Virginia Tech (2019, 2022–2025). Includes source-linked Section C text and PDF form answers, normalized admissions counts and rates, gender breakdowns, waitlists, test percentiles, rank, factor ratings, fees, and historical deadlines where extraction is reliable. Schools imported by counselors remain in the shared database independently of this seed. Read `PROJECT_BRIEF.md` for a new-conversation handoff.

Gender trends show ten metrics under the searchable, alphabetized **Gender admissions** group: applicants, admits, enrollment, admission rate and yield for male and female. Another-gender and unknown-gender source data remain in profiles and full exports, but are omitted from the trend picker. Profiles show a source-linked gender table; chart tooltips and CSV population columns use the selected group's counts. Categories follow each source, with men/women mapped to male/female labels. Missing categories stay missing; zero denominators do not produce rates.

School dropdowns include search in the library, Trends and comparison controls. A school selected or opened in the library carries into Trends with its available years; chart settings remain intact when changing tabs in the current page session. School metadata supplies first/last report years without inferring missing cohorts. Run `node scripts/check-school-navigation.mjs`, `node scripts/check-trend-availability.mjs` and `node scripts/check-trend-controls.mjs` against the local app to verify navigation, search, retained chart controls and existing graph behavior.

Existing records receive additive, source-hash-pinned enrichment from `data/gender-source-backfill.json` through `lib/saved-gender.ts`; existing metrics, counselor corrections, raw pages and metadata remain untouched in D1. Newly imported PDFs store parsed gender metrics directly. Sources with ambiguous answer placement or conflicting gender/status entries retain gaps and notes. In particular, Clemson 2016 enrollment labels appear misassigned in the publisher's report; gender enrollment/yield remain unfilled. Some existing counselor imports have overall counts that disagree with their source-backed gender totals; notes flag them, without replacing those saved totals.

The three new-school archives use official PDFs with URLs, SHA-256 and independently checked C1 totals in `data/new-archive-sources.json` and `data/new-archive-source-review.json`. TCNJ 2023 preserves printed overall totals despite inconsistent residency and gender breakdowns. Michigan 2018 preserves the stale Fall 2017 label but uses the reviewed 2018 cohort index. Shared parser improvements cover historical application/offer labels and sum annotations, complete gender columns with a separate Total, numbered subquestion rows, labeled percentiles and Unicode C7 boxes. Mixed survey pages now prioritize explicit CDS links over unrelated PDFs.

Reproduce source collection and import with `python scripts/collect_new_archives.py`, then `node scripts/download-villanova.mjs` if ordinary Python requests are refused for Villanova, rerun collection, and run `node scripts/import-new-archives.mjs`. Review source changes before refreshing generated seed entries. Run `check-new-archives.mjs`, `check-new-archives-browser.mjs`, `check-gender-metrics.mjs`, and `check-new-discovery.mjs` alongside affected existing-school checks. Browser checks use actual files cached by collection. Gender backfill collection uses a local snapshot of existing full reports; it never writes to the shared library.

## Use

The Schools view shows one latest matching profile per institution, with direct links from its headline figures to supporting source pages. Explore a school's reporting years in the Yearly reports view, switch years inside a profile, select up to four records to compare, or export the visible results/selection to CSV. Search includes all preserved Section C text. Full record downloads preserve evidence and source notes. "Not reported" means no normalized value is available; consult the source. Zero remains zero. Policies may refer to a later admissions cycle than the fall enrollment cohort.

## Data and expansion

Hosted persistence uses Cloudflare D1 SQLite. Reports have a unique institution/year key and indexed institution/year and year lookups. An FTS5 index, maintained by triggers, searches the record content. Both school profiles and yearly reports paginate in the database to 100 results; school grouping uses window functions before pagination. Full source records load on demand.

**Add school data** accepts an official Common Data Set archive webpage or direct PDF or Excel (.xlsx) URL. It discovers linked PDF and .xlsx reports, lets the user select up to 25 per batch, downloads bounded public sources through the server, and extracts filled form answers and selectable PDF text in the browser with PDF.js, or cached worksheet cell values from .xlsx workbooks. Each draft retains its source URL, SHA-256, physical PDF pages, Section C text, form answers, and per-metric evidence. The review screen supports corrections to counts, scores, factor ratings, policies and deadlines. The user must confirm review and supply the three C1 headline counts before saving. Rates are recalculated from reviewed counts. Existing school/year records require an explicit replacement choice. Reviewed records persist in the shared database; extracting a report alone does not save it.

The importer recognizes common CDS layouts, including modern forms and older text tables. Missing and ambiguous responses stay blank for review. It does not perform OCR, extract Excel 97–2003 (.xls), Word or HTML-only reports, bypass school server access restrictions, or crawl an entire university website. Download limits are 25 MB and 200 PDF pages. Use the school's CDS archive rather than its homepage; some scanned or unusual layouts need manual corrections or a separate source adapter. Public-source fetching checks URLs and DNS addresses, checks redirects, bounds response sizes, and never forwards visitor cookies or authorization headers.

Spreadsheet import (`lib/xlsx.ts`, `lib/extract-xlsx.ts`) reads .xlsx/.xlsm workbooks in the browser without a new dependency. The server identifies the downloaded content (not the link's extension), and discovery lists workbook links, including Box `/shared/static/` downloads, beside PDFs; .xls links only receive a note. Only CDS template worksheets (`CDS-A` … `CDS-J`, or `C - …`) are read, numbered A=1 … J=10 regardless of workbook order; Welcome, Answer Sheet and Definitions sheets are ignored. Each worksheet is laid out with the same cell text and column-width coordinates as the offline openpyxl adapters and parsed by the shared Section C rules, so the C1 reconciliation, conflict warnings and C7 mark positions match PDF behavior. Appended answer dictionaries (including the misspelled `Question Numer` header) are excluded from printed rows. Dictionary-only workbooks are read by template question number; C120–C131 residency rows are labeled by number and dropped with a warning if a Residency column contradicts it. Values are cached results; formulas are never recalculated, and blank formula results are not answers. Percent formats are scaled, whole numbers keep every digit, and dates print only the parts their number format shows (a deadline formatted `m/d` is `01/02`, without Excel's stored year). Evidence and saved sections cite worksheet cell references rather than PDF pages. `node scripts/check-xlsx-import.mjs` covers each rule and its ambiguity with generated workbooks, checks the tracked Cornell 2022/2023 and Clemson 2021 originals against reviewed values, and, when collection caches exist, checks every cached original workbook: each headline count equals its reviewed seed value or is left blank with a warning. `node scripts/check-xlsx-browser.mjs` runs the original Cornell workbook and a mixed PDF/workbook batch through the local app with mocked sources and saves.

Two shared-parser fixes came from these workbooks and apply to PDFs too. A bare `Unknown 47` row directly beneath a men/women row on the same page is that verb's unknown-gender count (Illinois 2017–2020); the men/women sum alone previously undercounted applicants and admits. An enrolled unknown row has no full/part-time status, so enrolled is left for review. The student/faculty ratio rule no longer reads VT 2024's reversed "1 to 17" as 1:1. When an explicit C1 total exceeds its gender breakdown (Illinois 2021, Clemson 2021), the total remains blank with both values listed for the counselor, as before.

JSON remains the structured interchange format for full record downloads and the validated `/api/reports` POST endpoint. `public/import-template.json` documents that format for source adapters and backups; replace its illustrative values and links before use. By default, POST performs strict inserts: an existing school/year returns 409 and rolls back the entire batch. Intentional replacements require the `X-Replace-Existing: true` header, which the browser sends only when the user checks the replacement box. Counts must be nonnegative integers; percentages must be 0–100; SAT/ACT percentiles must be whole-number scores on the supported scale in ascending order. Historical 2005–2016 SAT reports can retain composite scores up to 2400. Each record requires an HTTP or HTTPS source and source text. Site access is enforced by Sites; preserve the existing shared audience. The importer is a shared-library write operation behind that access boundary.

**ChatGPT file handoff:** choose **Add school data → Import from ChatGPT**. Download the instructions, attach them in the counselor's own ChatGPT conversation with an original report or direct official link, and ask for a downloadable Atlas import file. Upload that `.json` file in the same dialog. The instructions include the version 1 envelope, example, current metric catalog, source preservation rules, and limits (one school, 25 years, 5 MB). Source URLs are required; a file without a known URL needs an official report/archive link from the counselor. ChatGPT may need an uploaded original or clear page images when a website, scan, or checkbox cannot be read.

`lib/chatgpt-import.ts` checks the untrusted file before creating drafts: known metric names/types, source text for each supplied metric's evidence page, real source URL syntax, score/count/rate validation, unique school/year, and a single school/campus. Blank hashes remain blank with an explicit note. File claims of approval are ignored; every report starts unreviewed. Missing headline counts prevent saving, rates are recalculated, existing school IDs are matched in the review dialog, and replacement remains an explicit choice. Arbitrary workbook sheet names and companion-document URLs are retained. These checks do not verify that AI transcription or cited values match the original; counselor review is still required. Atlas makes no model/API requests in this workflow, and the automatic PDF/XLSX parser's extraction capabilities are unchanged.

The downloadable kit lives at `public/chatgpt-import-instructions.txt` and `public/chatgpt-import-template.json`. Regenerate it with `node scripts/write-chatgpt-import-kit.mjs` after changing metric definitions. Run `node scripts/check-chatgpt-import.mjs`, `node scripts/check-review-integrity.mjs`, and, against the local app, `node scripts/check-chatgpt-browser.mjs`; the browser check mocks all report reads/writes and never saves to production. The example is intentionally rejected until its placeholder school, URLs, and source text are replaced.

Clearing a metric in the review editor records it in `omitted_metrics`, so later source enrichment cannot refill it. Entering a new value removes that omission marker and keeps source evidence. Calculated class-size percentages are cleared whenever their supporting counts become incomplete or invalid. Run `node scripts/check-review-integrity.mjs` for SQLite-backed save conflicts, batch rollback, concurrent imports, explicit replacement, omissions, score validation and calculation regressions; it uses an in-memory database and never writes to production.

`data/reports.json` is the reproducible seed. `data/admissions.sqlite` is a portable SQLite copy, generated by verification (it is not the hosted runtime database). `data/sources/` caches original official PDFs/spreadsheets and extraction evidence with SHA-256 provenance.
